# Контрольные вопросы по лабораторной работе №5

## 1. Что такое React

React — библиотека JavaScript для описания интерфейса через компоненты. Компонент возвращает описание элементов, а React синхронизирует с ним DOM. Обновление состояния или props вызывает новый рендер; React определяет нужные изменения DOM. React не является сервером или базой данных. В LumiCalc он формирует плитку и ленту из mock-коллекции.

## 2. Чем props отличаются от состояния

Props — входные значения компонента, переданные родителем. Компонент не должен их изменять. State — собственная память компонента между рендерами; она изменяется через setter и вызывает следующий рендер. В LumiCalc Layout владеет применённым powerFilter, фильтр получает его через props. У самого фильтра minPowerWatt и maxPowerWatt — локальные state. После «Применить» callback передаёт новый диапазон родителю. Общие значения поднимают к ближайшему общему родителю, чтобы избежать расходящихся копий.

## 3. Компонент и элемент

Компонент — функция, описывающая часть интерфейса, например LightingEquipmentCard. React-элемент — результат JSX, например <LightingEquipmentCard lightingEquipment={equipment} />; он описывает тип компонента и его props. Элемент не равен DOM-узлу: компонент может вернуть несколько элементов, а DOM формируется при commit. key задаёт идентичность элемента среди соседей; equipmentId позволяет правильно сопоставлять карточки при фильтрации.

## 4. Как работает useState

useState(initialValue) возвращает текущее значение и функцию изменения. Setter планирует обновление, но не изменяет переменную уже выполняющегося рендера: она остаётся снимком состояния. Для изменения на основе предыдущего значения используют функциональную форму, например setIsLightingEquipmentDescriptionExpanded(expanded => !expanded). Объекты и массивы заменяют новыми значениями, а не мутируют. В Layout setPowerFilter получает новый объект диапазона.

## 5. Для чего нужен useEffect

useEffect синхронизирует компонент с внешней системой после commit: документом, таймером, сетью и т. п. Массив зависимостей содержит все реактивные значения эффекта. При изменении зависимости сначала выполняется cleanup прежнего эффекта, затем setup нового; cleanup также выполняется при размонтировании. Пустой массив означает отсутствие реактивных зависимостей, а не запрет дополнительного проверочного цикла StrictMode в разработке. В useLightingEquipment эффект читает mock после изменения powerFilter. Cleanup выставляет флаг false, поэтому устаревший Promise не обновит состояние. В страницах эффект меняет document.title. Саму чистую фильтрацию выполняет filterLightingEquipment.

## 6. Жизненный цикл и правила хуков

Монтирование — первое появление компонента; обновление — новый рендер из-за props или state; размонтирование — удаление. В функциональных компонентах рендер должен оставаться чистым, а setup/cleanup эффекта отвечают за синхронизацию. Это не буквальное соответствие «один useEffect = один метод жизненного цикла». Хуки вызывают на верхнем уровне компонента или своего хука, без условий и циклов. В LumiCalc смена equipmentId меняет key и перемонтирует содержимое ленты: раскрытое описание и ошибка старого видео сбрасываются.

## 7. Для чего нужны хуки роутера

useLocation сообщает текущий маршрут: Layout выбирает тёмное оформление ленты. useParams получает equipmentId из адреса, по нему находится опубликованная модель. useNavigate выполняет переход к следующей модели без полной перезагрузки документа. Link и NavLink создают клиентские переходы; NavLink также помечает активный пункт. Список для «Далее» берётся после фильтрации, поэтому переход 1 → 4 корректен и не сводится к id + 1.

## 8. Что делают Vite и Babel

Vite предоставляет сервер разработки, обновление модулей и production-сборку. TypeScript добавляет статические типы, TSX — JSX в TypeScript; типы не проверяют приходящий JSON во время выполнения. Скрипт npm run build сначала запускает tsc -b для проверки типов, затем vite build. Babel — отдельный компилятор JavaScript с плагинами для преобразования синтаксиса, в том числе JSX; он не является React или менеджером состояния. В проекте установлены Vite 8 и @vitejs/plugin-react 6: этот современный стек преобразует JSX через Oxc, а не Babel. Поэтому неверно говорить, что Babel обязательно работает внутри любой версии Vite. Знание Babel остаётся отдельным контрольным вопросом курса.

## 9. Почему приложение работает без БД и S3

lightingEquipmentMock импортируется в JavaScript-бандл; getLightingEquipmentList возвращает Promise с результатом чистой фильтрации. Здесь нет fetch, Axios или запросов к Go API. Файлы из public/media раздаёт сам сервер фронтенда. В Network видны JS, CSS, изображения, видео и HMR Vite, но нет API-запросов. Redux, Context, авторизация и подключение хранилищ не относятся к реализованной ЛР5.
